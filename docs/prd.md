# 需求文档

## 1. 应用概述

### 1.1 应用名称
低代码管理系统开发平台

### 1.2 应用描述
面向企业用户的多租户元数据驱动低代码管理系统开发平台。平台以演示租户（demo@yunshu.cn）为业务蓝本，将协同办公、项目管理、客户管理等业务模块封装为标准化应用插件并内置于应用市场，同时清空原有历史插件。新企业租户注册初始化后，默认仅开放「工作台」与「系统设置」基础菜单；管理员可通过应用市场按需安装组件，系统将动态向当前租户复制并注入对应的菜单与表单元数据，实现业务模块的即开即用与生命周期管理。同时在系统设置中提供统一的模型配置能力，支持配置国内各主流大语言模型，为系统内各项AI匹配能力提供底层服务支撑。

## 2. 用户与使用场景

### 2.1 目标用户
- 企业超级管理员：负责租户初始化配置，在应用市场安装、卸载业务组件，在系统设置中配置组织权限与AI模型参数。
- 企业普通员工：使用当前租户已安装组件提供的表单应用与审批流处理日常业务，并使用基于统一模型配置的AI匹配功能。

### 2.2 核心使用场景
- 新租户初始化：新企业租户注册并登录后，仅可见工作台与系统设置菜单，并在工作台引导提示下前往应用市场。
- 组件按需安装：管理员在应用市场浏览「协同办公」「项目管理」「客户管理」三款组件并执行安装，系统基于蓝本元数据为当前租户注入一级菜单与全部子应用菜单。
- 组件卸载与数据保护：管理员卸载已安装组件，系统隐藏并回收对应菜单路由，保留底层业务数据以便重装恢复。
- AI模型配置与调用：管理员在系统设置中配置并切换国内主流AI模型参数（API Key、接口地址、模型类型等），业务模块中的AI匹配功能统一调用该生效模型。
- 业务表单数据填报与查看：用户在已安装的业务模块中进行数据新建、编辑或详情查看，通过顶部面包屑导航掌握当前上下文层级并支持快捷返回。

## 3. 页面结构与功能说明

### 3.1 页面结构

- 导航与菜单架构
  - 顶部导航栏（租户信息、应用市场入口、用户信息）
  - 左侧主菜单栏
    - 默认基础菜单：工作台、系统设置（组织架构、角色权限、应用管理、AI模型配置）
    - 动态装配菜单：协同办公（含子菜单）、项目管理（含子菜单）、客户管理（含子菜单）
- 工作台（首页）
  - 基础看板与快捷入口
  - 未安装业务组件时的空状态引导卡片
- 新手引导
  - 应用市场入口高亮与安装指引遮罩
- 应用市场
  - 组件列表（仅展示协同办公、项目管理、客户管理三款内置插件）
  - 组件详情（展示组件名称、图标、简介、包含的子应用清单、安装/卸载状态与操作按钮）
- 业务模块（安装后可见）
  - 协同办公模块（请假申请、报销管理、借款管理、出差申请等子应用）
  - 项目管理模块（项目立项、项目台账、任务跟踪等子应用）
  - 客户管理模块（客户档案、客户台账、商机跟进等子应用）
  - 业务表单通用页面（新增页 /app/:fid/new、详情页 /app/:fid/:bizId、编辑页 /app/:fid/:bizId/edit）
    - 顶部通栏面包屑导航条（左侧装饰竖线、三段式面包屑文本、右侧返回按钮）
    - 业务表单内容区（包含表单字段与基于统一模型配置的AI匹配功能）
- 系统设置
  - 组织架构与成员管理
  - 角色权限管理
  - 已安装应用管理
  - AI模型配置

### 3.2 功能说明

#### 3.2.1 蓝本快照与组件封装
- 蓝本基准：以演示超管账号 demo@yunshu.cn 所在租户的现有元数据为基准快照，提取其菜单结构、表单定义、字段配置与审批流规则。
- 协同办公组件封装：包含协同办公一级菜单及其下全部子应用（请假申请、报销管理、借款管理、出差申请等审批类表单及菜单路由）。
- 项目管理组件封装：包含项目管理一级菜单及其下子应用（项目立项、项目台账、任务跟踪等数据表单及菜单路由）。
- 客户管理组件封装：包含客户管理一级菜单及其下子应用（客户档案、客户台账、商机跟进等数据表单及菜单路由）。
- 数据安全隔离：组件封装仅提取元数据结构定义作为模板，不包含 demo 租户的实际业务数据记录，防止数据污染。

#### 3.2.2 新租户极简初始化
- 默认菜单范围：新注册企业租户初始化时，仅生成「工作台」与「系统设置」（含下属组织架构、角色权限、应用管理、AI模型配置等子菜单），不预置任何业务模块菜单。
- 工作台空状态：在租户未安装任何业务组件时，工作台展示轻量提示卡片，引导管理员前往应用市场装配所需模块。
- 新手引导：保留首次进入且已安装组件数为 0 时的引导提示，高亮应用市场入口，支持一步直达并支持跳过。

#### 3.2.3 应用市场重构与展示
- 历史插件清理：清空应用市场原有的全部历史业务应用插件数据。
- 内置组件上架：仅上架「协同办公」「项目管理」「客户管理」三款标准化业务组件。
- 组件信息展示：卡片与详情页展示组件图标、名称、版本、功能描述、所包含的子应用列表及当前租户的安装状态（未安装/已安装）。

#### 3.2.4 组件安装与卸载生命周期
- 组件安装：
  - 管理员点击「安装」后，系统基于蓝本元数据快照向当前租户复制并注入对应的一级菜单与全部子应用元数据。
  - 安装完成后，左侧菜单栏即时渲染对应的一级菜单与全部子菜单入口，租户成员获得访问与填报能力。
- 组件卸载：
  - 管理员点击「卸载」并二次确认后，系统回收并隐藏左侧菜单中的对应入口及路由。
  - 卸载仅注销菜单与页面入口，租户历史已填报的业务数据物理保留；后续重新安装时自动恢复关联展示。

#### 3.2.5 系统设置 - AI模型配置
- 模型服务商配置：支持配置国内主流大模型服务商（包括通义千问、智谱GLM、MiniMax、百川、月之暗面等）。
- 参数项维护：提供模型服务商选择、模型名称/版本、API Key、接口地址（Base URL）等基础连接参数的配置与修改。
- 连通性测试：支持对当前填写的模型配置进行连通性校验，验证配置参数的有效性。
- 统一生效与分发：系统内所有业务模块中的AI匹配功能统一读取并使用系统设置中当前已启用的AI模型配置。

#### 3.2.6 业务表单顶部面包屑导航与AI匹配
- 覆盖页面范围：所有业务表单应用（BizApp）的新增页（/app/:fid/new）、详情页（/app/:fid/:bizId）及编辑页（/app/:fid/:bizId/edit）。
- 通栏布局与显示：独立显示在业务表单内容区最上方通栏，与表单原有页头内容并存。
- 面包屑内容结构：左侧展示装饰竖线与三段式层级路径「一级模块名 > 表单名 > 页面动作」：
  - 第一段：取当前业务表单所属的一级模块名称（如「客户管理」「协同办公」「项目管理」）。
  - 第二段：取当前子表单应用名称（如「客户档案」「请假申请」）。
  - 第三段：根据当前页面类型取对应动作名称（新建、编辑、详情）。
- 快捷返回操作：面包屑导航条右侧提供「返回」按钮，点击后返回上一级来源页面或当前表单列表页。
- AI匹配能力调用：表单相关AI匹配功能统一通过租户配置的全局AI模型提供分析与匹配输出。

## 4. 业务规则与核心逻辑

1. 快照复制隔离规则：组件安装过程为元数据深拷贝注入当前租户空间，各租户之间的组件元数据配置与业务数据完全隔离独立。
2. 默认最小化菜单规则：新租户注册成功触发初始化逻辑，强制仅写入工作台与系统设置的基础元数据配置。
3. 菜单动态映射规则：左侧菜单栏根据当前租户已安装组件状态实时拉取并渲染，安装即时显示，卸载即时隐藏。
4. 卸载数据保留规则：组件卸载操作仅变更组件安装状态并下线菜单路由，不得物理删除租户已产生的业务表单记录。
5. AI模型统一调度规则：各业务组件自身不独立绑定特定外部搜索或大模型插件，平台所有AI匹配场景统一解析并调用当前租户在「系统设置 - AI模型配置」中激活的模型参数。
6. 面包屑层级解析规则：进入表单新增、编辑、详情路由时，系统自动解析路由参数中的表单标识 fid 与动作类型，动态关联获取其所属的一级模块名称和表单名称并拼装为三段式文本。
7. 面包屑返回交互规则：点击面包屑条右侧「返回」按钮时，优先执行浏览器历史返回；若无历史来源则默认导航回该表单的数据列表页。

## 5. 异常与边界情况

| 异常/边界场景 | 触发条件 | 处理规则 |
|---|---|---|
| 组件安装失败 | 安装过程中元数据复制中断或网络异常 | 提示「安装失败，请重试」，回滚本次操作，不生成残缺菜单 |
| 卸载含有业务数据的组件 | 管理员在应用市场或系统设置执行卸载 | 弹出提示确认框说明「卸载将隐藏菜单入口，业务数据将安全保留」，确认后方可执行 |
| 重复点击安装 | 在安装请求处理中再次点击安装 | 按钮处于加载中禁用状态，避免重复注入元数据 |
| 未配置AI模型触发匹配 | 租户未在系统设置中配置有效模型时触发AI匹配 | 提示「未配置AI模型，请联系管理员在系统设置中完成配置」 |
| AI模型鉴权或请求失败 | 模型API Key失效、接口地址错误或服务商欠费超时 | 提示「AI模型服务调用失败，请检查模型配置」，不中断业务表单的基础保存与编辑流程 |
| 表单无归属一级模块 | 访问未挂载到一级模块下的独立表单路由 | 面包屑第一段降级展示为默认根模块名或直接展示「表单名 > 页面动作」 |

## 6. 验收标准

1. demo@yunshu.cn 演示账号菜单结构与表单配置完成调研与封装，形成协同办公、项目管理、客户管理三套独立组件模板。
2. 新注册企业租户首次登录系统，左侧菜单栏仅包含「工作台」与「系统设置」（含子菜单），无任何业务模块菜单。
3. 应用市场列表仅上架「协同办公」「项目管理」「客户管理」三款组件，历史旧插件全部清空。
4. 在系统设置中进入「AI模型配置」，能够选择国内主流模型服务商并保存 API Key 与接口地址等参数，且支持连通性校验。
5. 业务模块内触发AI匹配功能时，统一使用系统设置中当前启用的模型配置发起处理，不再依赖外部特定第三方单体插件。
6. 在新租户中安装「协同办公」组件后，左侧菜单栏即时出现协同办公一级菜单及其包含的全部审批子应用，且各子应用可正常打开并填报数据。
7. 在新租户中安装「项目管理」或「客户管理」组件后，左侧菜单栏即时出现对应模块及其子应用，功能立即可用。
8. 管理员卸载已安装组件后，对应菜单入口即时隐藏；重新安装该组件后，原先填报的历史数据可恢复查看。
9. 各企业租户之间的组件安装状态、模型配置与业务数据严格隔离，互不影响。
10. 打开任意业务表单的新增页、编辑页、详情页，内容区最顶部均正常显示独立通栏面包屑导航条，包含左侧竖线、正确的三段式文字及右侧「返回」按钮，点击可正确返回。

## 7. 本期不实现功能

1. 第三方开发者自主发布与上架自定义插件。
2. 应用市场组件的付费与计费订阅体系。
3. 跨租户直接共享或同步业务数据记录。
4. 面包屑路径文字的自定义配置与点击跳转任意历史中间节点功能。
5. 多AI模型的权重分流与多模型并发竞速调用机制。
